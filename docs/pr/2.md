# PR 2: Pin and fetch Firefox

Branch `pr2-pin-firefox`, based on `pr1-foundations`. Plan: `orbis-desktop-phase0.md`, section D, PR 2.

## What

- `upstream/firefox.json`: repository `https://github.com/mozilla-firefox/firefox`, tag `FIREFOX_160_0_RELEASE`,
  commit `2887d9de1f69c0e9776413da80e7ba0d1225dd9b`, and how they were verified.
- `scripts/fetch-firefox.ps1`: shallow fetch (depth 1) of exactly the pinned tag into `-Destination` (default
  `%USERPROFILE%\orbis_desktop_src\firefox`, outside the repo). Checks the remote tag with `git ls-remote` before
  downloading, checks the fetched commit again after, and checks out only if both equal the pinned SHA. Refuses
  destinations not on `C:`, inside the repo (or containing it), non-empty non-git folders, and git folders with a
  different origin. Sets `core.autocrlf=false` and `core.longpaths=true` in the checkout only.
- `scripts/check-firefox-currency.ps1`: reads `LATEST_FIREFOX_VERSION` from
  https://product-details.mozilla.org/1.0/firefox_versions.json; exit 1 when it is newer than the pin, exit 2 when
  the check itself fails.
- `scripts/firefox-pin.ps1`: shared pin reader and version comparison (dot-sourced by both scripts).
- `docs/UPDATING.md`: how to check and move the pin.

All scripts run in Windows PowerShell 5.1.

## Differences from the plan

- The plan named `scripts/check-currency.py` with unit tests; this PR uses PowerShell (owner's instruction), tested
  by hand as listed below. The daily GitHub workflow is PR 6.
- Default checkout path is `%USERPROFILE%\orbis_desktop_src\firefox` (owner's instruction), not `C:\orbis-build`.

## Verification

- `git ls-remote https://github.com/mozilla-firefox/firefox` (2026-11-11):
  `2887d9de1f69c0e9776413da80e7ba0d1225dd9b refs/tags/FIREFOX_160_0_RELEASE` and the same SHA for
  `FIREFOX_160_0_BUILD1`. No `^{}` line, so the tag is lightweight. The GitHub commits API returns that SHA as a
  commit dated 2026-11-04T17:51:23Z ("No Bug - Update configs after merge day operations a=release").
- Currency check, live: `OK: pinned 160.0 (FIREFOX_160_0_RELEASE) equals Mozilla's latest release 160.0; next release
  date in feed: 2026-11-20`, exit 0. With a 159.0.2 pin: `BEHIND`, exit 1. With a local feed saying 160.0.1: `BEHIND`,
  exit 1. With a 161.0 BUILD1 pin: `OK ... ahead`, exit 0. Bad pin tag or 404 feed: exit 2.
- Fetch script, against a dummy git repository in scratch (the real fetch was not run):
  - correct pin: OK, exit 0; second run: OK, exit 0; result is shallow with 1 commit at the pinned SHA;
  - wrong SHA: `REFUSED ... Nothing was fetched`, exit 1, no objects downloaded;
  - annotated tag: peeled commit accepted when right, refused when wrong;
  - missing tag: exit 1;
  - remote tag moved between the check and the fetch (simulated with a switching upload-pack): `REFUSED: fetched tag
    ... Nothing was checked out`, exit 1, HEAD unset;
  - destinations on `S:`, UNC, inside the repo, the repo's parent, a non-empty non-git folder, and a checkout with a
    different origin: all refused, exit 1, nothing created.

## Not verified

- The full fetch from GitHub (size, time, long paths in the real tree).
- That `core.autocrlf=false` is what the Firefox build expects on Windows (it keeps Mozilla's files byte-identical,
  which is what patches need).
