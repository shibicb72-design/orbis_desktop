# PR 3: Privacy layer

Branch `pr3-privacy-layer`, off `main`. Plan: `orbis-desktop-phase0.md`, sections B.5, C.2, C.3 and D (PR 3).

## What

- `overlay/distribution/policies.json`: 24 Firefox enterprise policies: telemetry, studies, accounts, VPN, updater,
  system add-on updates, sponsored content, AI, HTTPS-only, DRM, DoH, search engines, uBlock Origin install and its
  filter lists.
- `overlay/orbis.cfg`: 53 Firefox prefs (plus one Orbis marker pref) that no policy covers: the rest of telemetry
  and studies, Google Safe Browsing off with every Google endpoint blanked (as LibreWolf does), Widevine via
  Google's updater off, MITM priming, Contile and add-on recommendations off, Mozilla promotions off, region lookup
  off, captive-portal and connectivity checks off by default, and ETP Strict on a profile's first start.
- `overlay/defaults/pref/autoconfig.js`: the loader stub (`general.config.filename` = `orbis.cfg`, not obscured,
  sandbox left on).
- `docs/SETTINGS.md`: one row per setting with value, locked or default, reason and where Firefox 160 defines it;
  the pending defaults; the differences from Orbis for Android.
- `scripts/check-settings.py` (run with `python -I`): checks the three files against the pinned Firefox 160 source.
- `README.md`: the Safe Browsing sentence. `AGENTS.md`: project map and the new check command.

Owner decisions applied (2026-11-12): no Google Safe Browsing; uBlock Origin installed automatically from AMO
(`normal_installed`, not bundled) with its default lists plus "Phishing URL Blocklist"; Windows SmartScreen not
touched; no telemetry, studies, accounts or sync; English only (language packs blocked).

How the files reach the browser: PR 4's `apply-overlay.ps1` copies them into the checkout; PR 5 puts them in the
package (`distribution\policies.json`, `orbis.cfg` and `defaults\pref\autoconfig.js` in the install folder).

## Defaults pending Shibi's OK

Fable's recommended defaults, used here until Shibi decides:

- **Locked**: telemetry, studies, Firefox accounts and sync, sponsored content, AI chatbot. The AI `Default` also
  blocks link-preview key points, smart tab groups, smart window, PDF alt text and speech recognition; translation
  stays available.
- **Adjustable**: ETP Strict (set on a profile's first start, then the user's choice), HTTPS-only on in all windows,
  search engine DuckDuckGo (Brave Search and Startpage added, as on Android).
- **DRM off** (user can turn it on).
- **DNS over HTTPS off** (`network.trr.mode` 5) and **captive-portal and connectivity checks off**, all adjustable.
  With the captive-portal check off, hotel, airport and café Wi-Fi login pages do not open by themselves.
- **`about:config` open.**

## Pending Shibi

Three defaults from the review need Shibi's decision. They are unchanged in this PR and listed in
`docs/SETTINGS.md` ("Network calls that remain"):

- **uBlock Origin list overwrite at every launch.** `3rdparty` `toOverwrite.filterLists` is re-applied by uBlock
  Origin at every start, so a user who adds or removes a list loses that change at the next start. Options: keep, or
  drop `toOverwrite` and accept that the user (or uBlock Origin's own defaults) decide the lists.
- **Push websocket** (`wss://push.services.mozilla.com`). Opened at every start with a per-profile ID. Remote Settings
  uses it to receive security data quickly; websites use it for notifications. Options: keep (Firefox default), or
  turn off (`dom.push.enabled`), which delays Remote Settings to its periodic poll and breaks site notifications.
- **AMO metadata cache** (`extensions.getAddons.cache.enabled`). Sends the IDs of installed add-ons to
  `services.addons.mozilla.org` about once a day for names and icons. Options: keep (Firefox default), or turn off.

## Differences from Orbis for Android

Read from `work-orbis` (read-only): `GeckoEngineImpl.kt` (`GeckoRuntimeSettings`, `ContentBlocking`),
`BrowserSettings.kt`, `SearchEngine.kt`.

- Safe Browsing: Android on (`SafeBrowsing.DEFAULT`); desktop off (owner decision).
- `about:config`: Android blocked (`aboutConfigEnabled(false)`); desktop open (pending).
- ETP level: Android Strict and fixed (per-site exceptions only); desktop Strict but the user can change the level.
- uBlock Origin: Android installs it after the user agrees, with uBlock Origin's default lists; desktop installs it
  automatically and adds the Phishing URL Blocklist (owner decision).
- Search engines: same default (DuckDuckGo) and same five engines, but desktop also keeps Firefox's built-in list for
  the region (for example Wikipedia, eBay, Perplexity). Removing engines was not decided.
- DRM, captive portal, DoH: Android leaves GeckoView's defaults; desktop turns them off (pending).

Same as Android: ETP Strict with strict social-tracking protection, third-party cookies isolated per site in normal
and private tabs, HTTPS-only in all tabs by default, search suggestions on except in private windows.

## Design notes

- `EnableTrackingProtection` is not used: when it sets a category, Firefox locks it
  (`Policies.sys.mjs`, "These are always locked"). Strict is set from `orbis.cfg` once per profile instead, guarded by
  the Orbis pref `orbis.privacy.etpStrictApplied`, so a later user choice is kept.
- `GenerativeAI` and `DisableFirefoxAccounts` are not used: Firefox ignores them when `AIControls` and
  `DisableAccounts` are present.
- Fable's draft listed a `CrashReportsSubmit` policy; it does not exist in the 160 schema. Crash reports are covered
  by the build option (PR 4) and two locked prefs.
- Three pref names from the draft and LibreWolf do not exist in 160 and were replaced:
  `toolkit.telemetry.dap_enabled` (now blanking `toolkit.telemetry.dap.leader.url` and `.helper.url`),
  `messaging-system.rsexperimentloader.enabled` (now `nimbus.rollouts.enabled`), and
  `browser.newtabpage.activity-stream.feeds.telemetry` (dropped; the master switch
  `browser.newtabpage.activity-stream.telemetry` and the policy cover it).
- uBlock Origin applies `toOverwrite.filterLists` at every launch (`restoreAdminSettings()` in its `start.js`), so
  a user's own list changes last only until restart, and regional lists are not auto-selected.

## Changes after Fable's review

Must-fix:

- `media.gmp-widevinecdm.allow-chromium-update` and `media.gmp-widevinecdm-l1.allow-chromium-update` locked false.
  `GMPInstallManager.checkForAddons()` calls `adjustForChromiumUpdateService()` before the DRM-off filter, so with
  the Windows default (true, `firefox.js` lines 2606 and 2612) Firefox asked `update.googleapis.com` about Widevine
  every day even with DRM off. Confirmed in `GMPInstallManager.sys.mjs` (line 374 and 391-407).
- Policy `DisableSystemAddonUpdate: true`. `DisableAppUpdate` does not stop system add-on updates from
  `aus5.mozilla.org` (`extensions.systemAddon.update.enabled` is true in `firefox.js`). The policy disallows
  `SysAddonUpdate` (`Policies.sys.mjs` line 1443).

Should-fix:

- Locked false: `security.certerrors.mitm.priming.enabled`, `browser.safebrowsing.realTime.enabled`,
  `browser.safebrowsing.globalCache.enabled`, `browser.topsites.contile.enabled`, `extensions.getAddons.showPane`,
  `extensions.htmlaboutaddons.recommendations.enabled`.
- `docs/SETTINGS.md` has a new section, "Network calls that remain": Remote Settings, the push websocket, the GMP
  manifest and OpenH264, AMO updates and the uBlock Origin install, uBlock Origin's own list downloads, the AMO
  metadata cache, OCSP, DuckDuckGo suggestions, translation models and geolocation, each with host, when and why it
  stays. The old "unverified Widevine" bullet is gone (now locked).
- The captive-portal note (Wi-Fi login pages do not open by themselves) is in the pending table and above.

Nits:

- `check-settings.py`: the `//` comment cut no longer cuts inside string values. Before, a line such as
  `lockPref("x", "https://...")` was cut at `https:` and the pref was skipped without a word. A scratch test with
  four planted lines (an unknown pref with an `https://` value, a `//` inside a string, a duplicate, and a wrong
  type) now fails on each.
- The Startpage-region wording is gone (region lookup is off, so it was moot).
- `UserMessaging` side effect noted: `FeatureRecommendations` false with `Locked` also sets and locks
  `browser.translations.mostRecentTargetLanguages`.
- Cookie notices (plan C.2): **added by policy.** uBlock Origin has them (`assets.json`, group `annoyances`, off by
  default). Added the "EasyList/uBO – Cookie Notices" pair, `fanboy-cookiemonster` and `ublock-cookies-easylist`;
  the AdGuard pair is not added. Firefox's own `cookiebanners.service.mode` stays off, as the plan says.
- Mozilla promotions locked off, each name checked in the 160 source: `signon.firefoxRelay.feature` = `""` (not one
  of the four values `LoginHelper` treats as available), `browser.contentblocking.report.monitor.enabled` (Monitor
  card; already false in 160), `browser.vpn_promo.enabled` (VPN card, read by `protections.mjs` and ASRouter),
  `browser.contentblocking.report.show_mobile_app` (mobile-app promotion on the same page), `browser.uitour.enabled`.
